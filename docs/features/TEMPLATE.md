# 功能指南模板

> 复制本文件为 `docs/features/<功能名>.md`，按下面七节填写。
> **每个 ✅ 功能都必须有一份**（见 [`FEATURES.md`](../../FEATURES.md)）。
>
> 写的时候记住读者是**使用者**，不是维护者：他要的是「怎么用」和「别踩什么坑」，
> 不是内部实现。内部原理放 `docs/M*-report.md`。

---

## 1. 这是什么 / 什么时候用它

一句话说清用途。再补一句「什么时候**不**该用它」——这往往比正面描述更有用。

## 2. 最小示例

一段**能直接跑**的代码（不是伪代码）。如果它需要配套命令，写出来：

```sh
cargo run -p deer-gui --example <示例名>
```

## 3. 完整 API

用表格列出可用的类型/函数/属性，逐个说明。**别只列名字**——要写清参数含义与默认值。

## 4. 自检（怎么确认你真的用对了）

给出**可验证**的检查手段，而不是「看起来应该对」：

```rust
// 断言式自检，例如：
assert!(某种不变式, "错误信息要说清哪里不对");
```

## 5. 常见坑

每条写清：**现象 → 原因 → 怎么改**。只写真踩过的，不要凭想象凑数。

## 6. 相关

- 相关功能：链接到其它指南
- 内部原理：链接到 `docs/M*-report.md`
- 边界：这件事**做不到**什么（很重要）

## 7. 检查清单（发布前过一遍）

- [ ] 示例能跑：`cargo run -p deer-gui --example <示例名>` → `exit=0`
- [ ] 示例有自检断言（不是「跑成功就算」）
- [ ] `FEATURES.md` 已登记（状态 / 指南链接 / 示例命令都对）
- [ ] 如果属于新手主线，`docs/TUTORIAL.md` 已更新
- [ ] 明确写了「做不到什么」
